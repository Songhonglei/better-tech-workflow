# 转盘 · 抽奖与随机点名

一个现场抽奖工具：三维转盘（或滚动点名）从名单里随机抽人，按奖品档位逐档开奖，
记录中奖结果，并能导出海报 / CSV / 分享链接。

## 语言

网站语言跟随用户 query 的语言。本仓库是中文版本，界面文案均为中文。

## 开始之前：先问用户

加载网站之前，先用 ask_user 工具问用户几个问题：

1. **（必问）是否需要把网页变成全栈应用？** 现在的版本是纯前端：名单、奖品配置
   和中奖记录全部保存在浏览器 localStorage 里，换一台设备、换一个浏览器就没了。
   全栈化意味着增加服务端数据库，名单与中奖记录可以持久保存、多设备同步、多人
   协同操作。
2. 配色偏好？默认是「暖纸 + 标本色盘」：暖白纸底加网点，盘面是万寿菊 / 赤陶 /
   鼠尾草 / 藕粉 / 柠檬 / 杏 / 灰蓝 / 骨白八块低饱和色，另有深色主题。也可以
   换成用户的品牌色。
3. 使用场景是什么？年会抽奖、课堂随机点名、直播互动、活动签到……场景决定默认
   名单、奖品档位（默认特等奖 / 一等奖 / 二等奖 / 三等奖）和界面文案。
4. 是否需要自定义品牌信息？比如页面标题、结果海报的落款与样式。

如果用户不回答任何问题，直接按现状加载默认网站文件，不要擅自改动。

## 这是什么

纯前端单页应用（React 19 + Vite + three.js），无后端。主要功能：

- 三维转盘抽奖：扇区角度 = 权重占比，指针停在抽中的人；设备不支持 WebGL 时
  自动退化为滚动点名（老虎机式），功能不打折
- 奖品分档：名额抽满自动进入下一档，每轮可一次抽多人
- 规则开关：不重复中奖 / 按权重设置概率 / 扇区上显示概率 / 音效
- 中奖记录、CSV 导出、Canvas 绘制的结果海报、把名单与奖品编码进 URL hash 的
  分享链接（对方打开链接即载入同一份配置，无需服务器）
- 明暗两套主题，八个扇区色号在两套主题里完全一致

文件结构（node_modules/ 是依赖、dist/ 是构建产物，均省略）：

```
index.html                    入口；#root 用 display:contents，不额外生成盒子
package.json / vite.config.ts / tsconfig*.json
public/fonts/                 Geist 可变字重 + Geist Mono（woff2）
src/main.tsx                  React 挂载，按 kit → tool → app 顺序加载三层 CSS
src/App.tsx                   全部界面与交互（四个屏：抽奖台 / 中奖 / 名单与奖品 / 记录）
src/components/SwitchRow.tsx  开关行组件，结构与 tool.js 的 switchRow() 一致
src/lib/draw.js               状态结构、示例名单、默认奖品档位、存档清洗
src/lib/wheel.js              三维转盘引擎（three.js），详见下文
src/lib/kit.js                通用层：主题切换、toast、下载、CSV 等
src/lib/tool.js               工具共享层：海报、分享链接、屏切换、底部表单、音效、彩带、计时
src/styles/kit.css            共享设计令牌与基础样式
src/styles/tool.css           壳层样式：twopane 布局、屏切换、底栏、底部表单、海报预览
src/styles/app.css            本页视觉：暖纸色板、网点纹理、中奖屏、奖品行
```

它可以被用户的潜在需求变成别的用处：课堂随机点名器、直播间抽奖、饭局决定器、
活动签到抽奖、加权随机选择器等等。如果用户有特定需求，按需更改网站的文字内容
（App.tsx 里的界面字符串、draw.js 里的默认名单与奖品档位）或媒体内容（配色令牌
在 app.css 的 `:root`，海报样式在 tool.js 的 `poster()`）。如果用户只是想看看
这个网站，直接加载即可，不要改任何东西。

可选：如果符合用户的需求，你可以使用图像和视频生成工具。

## 技术要点（3D / 渲染）

转盘不是 DOM 动画，而是一台用 three.js 搭的「纸上机器」，全部在
`src/lib/wheel.js`，文件内注释写得很细，动手改之前先通读。没有自定义 GLSL，
全部用内置 PBR 材质调到平涂效果。要点：

- **几何**：盘身是一个有厚度的圆柱（CylinderGeometry），每个扇区是一块
  CircleGeometry 楔形，角度 = 权重占比（`slices()`）。盘面在 XY 平面、法线
  朝 +Z，整组后仰 0.30 rad 露出厚度；指针在 +Y 正上方，要让第 i 格停在指针下，
  转到 `rotation.z = π/2 − mid` 即可。
- **颜色诚实**：MeshStandardMaterial 做平涂（metalness 0、roughness ≈ 0.9、
  envMapIntensity 很低），配合 `NoToneMapping` + sRGB 输出，让屏幕上的颜色和
  CSS 令牌（如 `#f5b81c`）完全一致 —— ACES 之类的色调映射会把饱和度压掉一档。
  八个色号从 CSS 变量 `--s1…--s8` 现读（`palette()`），不写死，切主题不会脱节。
- **环境图**：不引 HDR 文件，用 PMREMGenerator 从一个小场景现烘 —— 一张 8×128
  的竖直渐变 canvas 加三块中性自发光板（白顶光 / 侧补 / 压暗背光）。哑光漆面
  也需要有东西可反，否则阴面掉成脏色；但放彩色板会把整台机器染上那个色相。
- **灯光**：半球光为主（均匀照亮平涂色），聚光只留一点方向感和一圈影子，
  ShadowMaterial 圆片做地面接影。灯光两套主题共用，不跟着 `--bg` 走。
- **名牌**：每个扇区一张 CanvasTexture 贴片，每帧反向转回水平
  （`l.rotation.z = -angle`），旋转中字始终是正的。字色按扇区亮度二选一
  （墨或米白，阈值 0.34；注意 THREE.Color 存的已是线性分量，别再套传递函数）。
- **性能策略**：像素密度一上来给满（封顶 2x），清晰是默认；静止时 tick 按
  66ms 节流（约 15fps），抽奖期间 `setSpinning(true)` 跑满帧；前 12 帧测中位
  耗时，<11ms 再把阴影加回来（开关 shadowMap 会换着色器，材质要 needsUpdate），
  >26ms 把像素密度降回 1。
- **主题切换**：只改该改的 —— 盘框 / 指针颜色 + 重烘环境图（`rethemeGL()`），
  并 setTimeout 约 260ms 等 CSS 过渡跑完再动，避免几百毫秒的重建把过渡冻住。
- **降级**：`initGL()` 失败（无 WebGL）自动切到滚动点名，rolling 层、canvas、
  中心按钮三样一起换。
- **音效**：WebAudio 现合成的咔哒声跟着经过的格子走，减速时自然变稀；没有
  音频设备时静默失败，不影响抽奖。

其它：结果海报是 Canvas 2D 两遍绘制（先量后排，见 tool.js 的 `poster()`）；
分享链接把配置 deflate + base64url 编码进 location.hash（`Tool.share`），
不经过任何服务器。
