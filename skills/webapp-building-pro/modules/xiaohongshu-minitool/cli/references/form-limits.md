# 填写提示与发布前检查

用于新建、更新版本和修改基础信息。收集资料时就提示对应限制，收到内容后立即检查；不要等到上传完或 submit 报错才提醒。已有合格资料直接复用，只集中询问缺失或不合格的部分。

以下规则核对自 2026-10-22 的 creator-publish 本地源码（HEAD `fe58a2752`）及当前 CLI；是 Skill 的准备与检查规则，不表示 CLI/API 已实现同样校验，也不证明线上审核一定通过。

## 对用户展示的字段要求

| 资料 | 填写时的提示 | Agent 检查与处理 |
| --- | --- | --- |
| 名称 `appName` | 必填，最多 14 个字符 | 不能为空或全空白；按原字符串的 JavaScript `.length` 计数，显示“当前 n/14”。超限给出保留原意的精简建议，不静默截断用户命名。 |
| 简介 `slogan` | 必填，用一句话说明用途，最多 14 个字符 | 同名称：非空白、`.length <= 14`；Agent 起草的文案也要先计数，避免让用户改写已知不合格的建议。 |
| 图标 | JPG/JPEG/PNG，单张不超过 5 MiB，正方形 1:1 | 网页选择文件后强制正方形裁剪，并输出 512×512 JPEG；CLI 不会自动裁剪。上传用于发布的图标前读取实际格式、字节数和尺寸，按 1:1 准备；512×512 是网页输出尺寸，不宣称是后端唯一允许尺寸。 |
| 封面 | JPG/JPEG/PNG，单张不超过 10 MiB，宽高比 3:4 | 网页固定 3:4 裁剪后输出 JPEG，未固定输出像素大小。CLI 需提前准备好比例，检查 `width * 4 === height * 3`；不能虚构最低分辨率。 |
| 代码包 | ZIP，不超过 10 MiB，根目录直接有 index.html | 网页检查 .zip 后缀和大小；CLI 还检查文件非空、ZIP 有效、解压合计不超过 30 MiB及路径安全。由 Agent 检查，不让用户手算大小或提供哈希。 |
| 版本 `version` | 三段数字，例如 1.0.0；更新使用新的版本号 | 网页正则为三段数字；CLI 更严格，每段除 0 外不能以 0 开头，不允许 beta 后缀。新建可建议 1.0.0，更新先查历史再建议版本，不随意覆盖用户已有版本。 |
| 类目 `categories` | 选择 1 个最贴合用途的类目 | 使用当前 CLI config 返回的 categories code。网页的场景标签也为单选，但网页 tagId 与 CLI category code 不是可直接互换的字段。 |
| 权限 `authorizations` | 仅选择功能确实需要的权限；无需求则明确说明“不需要权限” | 网页要求明确选择权限或“不需要权限”。Agent 根据项目与已有信息判断；不能确定时与其他缺项一起问，不把未知需求默认为无权限。CLI 的无权限值是空数组，不传“不需要权限”字样或额外布尔字段。 |

计数与大小的细节：普通中文、英文字母、标点和空格一般各计 1；许多 emoji 计 2 或更多，不能按视觉上的图形个数计数。前端先用 trim 判断是否空白，但对未 trim 的原字符串计长。输入框的 maxlength=19 仅为允许超限后展示错误，真正提交上限仍是 14。网页标注 MB，代码实际使用 `1024 * 1024`，即 5 MiB=5,242,880 字节，10 MiB=10,485,760 字节；恰好等于上限可通过大小检查。

## 少交互提示示例

只问缺少的项，并把限制放在同一句话里。例如仅缺名称、简介和图片时：

> 代码包已找到。我会根据项目起草名称和一句话简介（各最多 14 个字符），并按现有设计生成图标（JPG/PNG、≤5 MiB、1:1）和封面（JPG/PNG、≤10 MiB、3:4），随后上传并生成手机预览二维码；预览交付后再通过一次 AskUser 确认是否提交审核。

已从项目确定的内容先给草稿和检查结果，不要求重新填写。例如“名称「眼力侦探社」5/14；简介「寻找画面中的不同」8/14；图标尺寸 512×512、大小合格”。只有真正读过文件才能报告尺寸/大小合格。

文本超限时说明具体计数及上限，给出一两个合格候选，并把其他缺项放在同次交接中。纯查询、仅上传 ZIP、仅预览时不要额外索要送审资料。edit 每次必须同时传入 `appName`、`slogan`、`iconFileId`，后端不支持只传其中一个参数；按 [修改基础信息](workflows.md#6-修改基础信息) 补齐并检查。未修改项复用可信的现有值，无需用户重新起草文案或上传图片；现有值无法确定时先补齐，不能省略或猜测。

edit 的三项必传字段都必须是非空白字符串：任意一项缺失、为 `null`、空串 `""` 或纯空白，后端都会拒绝整个请求；复用现有值时也要检查。edit 的 `coverFileId` 为可选字段，可以省略，不要求为此补交封面；需要修改封面时传入新的封面 fileId。

图片不合格时指出实际格式、字节数或宽高比。需要转换/压缩/裁剪时保留原图，使用可用且获授权的图片工具处理并复检；不要将改文件后缀当成格式转换。不能检测或处理时说明缺哪项能力，请用户提供合格素材，不声称已经通过。裁剪影响主体内容时给出处理结果供用户核对，可与预览确认合并。

## CLI 与网页的边界

- CLI 的通用 image 上传接受 PNG/JPEG/GIF/WebP，且统一检查 10 MiB；这不等于网页图标允许 GIF/WebP 或 10 MiB。用于小工具发布的素材按上表准备。单纯上传其他图片时不要把网页图标限制误用到所有 image 上传。
- 当前 CLI 不检查名称/简介 14 字符上限，也不检查图标 5 MiB 和图片比例；dry-run 成功不能代替 Agent 的这些前置检查。
- 网页有《小工具发布安全规范》的勾选项，以及高级能力配置；当前 CLI 没有相应协议确认参数或高级能力字段。不要自动代用户接受协议，也不要向 JSON 添加 agreeProtocol、advancedAbilities 或使用不存在的 --protocol-ack。用户明确需要这些网页能力时说明当前 CLI 能力缺口，不能默默丢弃需求。
- 网页新建/更新须部署成功才能提交。Skill 的对应流程仍是上传成功 → 为实际送审内容生成二维码 → 用户扫码确认通过 → submit；表单校验通过不能替代扫码确认。

## 维护时核对的源码

路径相对于 creator-publish 仓库；可获得源码时以当前实现复核，规则变化后更新本页，不凭旧快照宣称线上已同步：

- `packages/ugc/src/types/redApp.ts`：RED_APP_FORM_LIMITS、RED_APP_VERSION_REGEX。
- `packages/ugc/src/containers/creator/pages/RedApp/AppForm.vue`：validateName/validateSlogan/validateVersion、单选场景、权限选择、协议与提交状态。
- 同目录 `components/AppBaseEditModal.vue`：编辑名称、简介的同样限制。
- 同目录 `components/IconUpload.vue`：格式、5 MiB、1:1 裁剪和 512×512 输出。
- 同目录 `components/CoverUpload.vue`：格式、10 MiB、3:4 裁剪。
- 同目录 `components/AppUpload.vue`：ZIP 后缀和 10 MiB。
- `packages/ugc/src/store/redApp.ts`：isFormValid 的非空、长度、版本、图片、类目及发布状态检查。
- 当前 CLI 的 `cli/redapp/index.mjs`、`cli/redapp/files.mjs`：支持字段、版本格式与文件检查。网页字段和 CLI 字段以各自接口为准。
